# 제품 로드맵

## 원칙

- 사용자 가치가 끝까지 이어지는 작은 vertical slice를 먼저 완성한다.
- 커뮤니티는 기능 수보다 콘텐츠 품질, 신뢰, 중재 도구를 우선한다.
- 원본 UI 학습 단계와 독자 서비스 단계의 브랜드·데이터 경계를 분명히 한다.

## Phase 1 — UI Study MVP (완료)

- 반응형 3열 홈과 카테고리 필터
- 추천 스토리, 인기/신규 피드, Build Board
- 검색, 업보트, 글 작성, 가입, 뉴스레터 데모
- 제품/아이디어/그룹 디렉터리
- 디자인 토큰, 타입, 정적 데이터 분리
- 프로젝트 운영 문서

완료 기준: 타입 검사와 프로덕션 빌드가 성공하고 1440/768/390px에서 핵심 콘텐츠가 손실되지 않는다.

## Phase 2 — 실제 서비스 기반 (다음)

- NestJS 또는 선택한 백엔드의 REST API
- PostgreSQL 스키마: users, posts, comments, votes, products, groups, memberships
- 이메일/소셜 인증, 세션·권한 정책
- 게시물 CRUD, Markdown 에디터, 댓글 스레드
- 서버 기반 정렬: newest, daily, weekly, monthly
- 이미지 업로드와 변환 파이프라인
- React Query 계열 서버 상태 계층과 전용 라우터 도입

완료 기준: 두 사용자가 서로의 글·댓글·업보트를 확인하고, 권한과 중복 투표가 서버에서 보장된다.

## Phase 3 — 커뮤니티 운영

- 신고, 숨김, 차단, 스팸 점수
- 운영자 검토 큐와 감사 로그
- 그룹 생성·가입·역할
- Build Board 일일 집계 작업
- 알림 인박스와 이메일 선호 설정
- 검색 색인과 태그 추천

완료 기준: 운영자가 코드 수정 없이 유해 콘텐츠와 스팸을 처리할 수 있다.

## Phase 4 — 성장과 수익화

- 독자 브랜드 및 디자인 시스템 완성
- 구독 콘텐츠와 결제
- 광고/스폰서 슬롯의 명확한 라벨링
- SEO용 SSR/SSG 전환 검토
- 추천 피드 실험, 이벤트 분석, A/B 테스트
- 다국어와 접근성 WCAG 2.2 AA 감사

## 바로 이어서 할 백로그

1. 독자 서비스명과 브랜드 방향 확정
2. 핵심 사용자(예: 한국 1인 개발자)와 첫 커뮤니티 범위 확정
3. API 계약과 DB ERD 작성
4. 인증 포함 게시물 vertical slice 구현
5. 신고·중재 정책을 공개 베타 전에 구현

## 제외/보류

- 현재 샘플에서 실제 결제, 이메일 발송, 광고 등록은 동작하지 않는다.
- 업보트 외 데이터는 새로고침하면 초기화된다.
- 원본 사이트의 비공개 API나 인증 흐름을 역공학하지 않는다.
